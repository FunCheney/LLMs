# INC-5 · 演练自己假绿：三条"永远会过"的断言

- **发现时间**：W11 D2 / D3（写混沌演练与 Timeline 时，被实跑数字否掉）
- **严重度**：P1（不是产品故障，是**证据失效**：报告里的绿色是假的）
- **影响面**：所有"我以为测了"的地方

## 1. 现象

三条断言，代码全对、测试全绿、报告全好，但**它们证明的东西不存在**。

### 1.1 `expected_calls = threshold × max_attempts` 少了一个乘数

写入的期望：熔断阈值 3、`max_attempts=2` → 上游调用 `3×2 = 6`。
实跑：**18**。

少的是**候选链**：一次 `gateway.chat()` 会依次试 `qwen3.7-plus → deepseek-flash →
gpt-4o-mini` 三条候选，每条再重试 `max_attempts` 次。真实倍数是
`放行次数 × 候选链长度 × max_attempts`。

**真正的风险不是数字错，而是断言把两件事混成了一件**：这个乘积属于 `LLMGateway`
（它的重试与 fallback 是设计如此），而熔断器的贡献必须**恰好是 0**。
混在一起断言，"链路多试了一次"和"熔断器自己重试了"看起来一模一样。

修法：拆成两条——总数比对链路预算；单独记 `calls_after_open == 0` 证明熔断器没放大。

### 1.2 半开"只放一个探测"用 5 个并发 `gather` 测，实测 5 个全放行

第一反应是"熔断器漏判"。实际不是：`httpx.MockTransport` 的 handler 是**同步**的，
探测一次到底、中途不让出事件循环；第一个调用返回时状态已回到 `CLOSED`，
后 4 个被正常放行——**这是对的**。

真正要测的性质是"**探测还在飞行时**，其余请求被快速拒绝"。用一对 `asyncio.Event`
把探测停在半空，它才可观测。改完后：飞行期间 0 次上游调用、4 个拒绝。

### 1.3 一个 `error` 字段被最后一条错误覆写

`Scenario.error` 每轮无条件赋值，于是 F1 报告里显示 `CIRCUIT_OPEN`（最后几轮是被拒的），
真正要看的 `UPSTREAM_TIMEOUT` 被冲掉。拆成 `upstream_error` / `last_refusal` 两个字段。

### 1.4 附：Timeline 的时间全部挤在 `00:00`

`ResumableRunner` 在循环外读一次时钟，所有步骤共用同一个 `now`。
表格照样对齐、照样好看，但"哪一步在等外部、等了多久"这个唯一的信息没了。

改法是把 `now = self.clock()` 挪进循环体。**这类 bug 不报错，只让仪表变瞎。**

## 2. 根因（三条共因）

| 共因 | 表现 |
|---|---|
| **断言写的是"我以为的实现"，不是"应有的性质"** | 1.1、1.2 |
| **一个变量承载两个含义** | 1.3（"最后一次错误"既想表达上游、又想表达我们拒绝） |
| **验证依赖的替身比真实世界快/整齐太多** | 1.2（同步 mock）、1.4（一次时钟） |

## 3. 分叉实验：重试到底值不值

为验证 ADR-003 的重试策略，做了一次真实对照（固定随机种子，50% 上游失败率，200 请求）：

```bash
uv run python evals/scripts/w11_fork_ablation.py
```

| `max_attempts` | 成功率 | 上游调用 | 每成功一次调用 |
|---|---|---|---|
| 1 | 53.0% | 200 | 1.89 |
| 3 | **87.5%** | 336 | **1.92** |

结论与我原本的预期**相反**：我以为"重试让成本翻倍"，实际**每次成功的成本几乎不变**
（1.89 → 1.92）。原因是失败的尝试本来就是拿到一次成功所必须支付的开销；
重试多花的流量**换来了更多成功的请求**（106 → 175），而不是"同一批成功多花了两倍钱"。

翻倍的是**绝对流量**（200 → 336，+68%），不是**单位成本**。
这两个数在容量规划里指向不同动作：前者要扩配额，后者要改策略。

口径声明：注入层是内存 `MockTransport`，**延迟不在本实验口径内**，所以不报 p95——
把 0.1ms 与 0.4ms 印进报告，会被读成"重试让延迟变差四倍"。

## 4. 回归用例

| 用例 | 钉住什么 |
|---|---|
| `test_circuit_breaker.py::test_breaker_never_retries_by_itself` | 熔断器不做第二次重试（`fn` 调用数 == 放行次数） |
| `test_circuit_breaker.py::test_gateway_with_breaker_stops_reaching_adapters_once_open` | 接线真的接上了（没接的熔断器在单测里永远是对的） |
| `test_resume_timeline.py::test_timeline_shows_retry_with_unchanged_arguments` | 时间轴能区分"参数未变的重试"与"改了参数再试" |
| `evals/scripts/chaos.py` 的 `calls_after_open` 列 | 熔断打开后上游调用必须为 0（每次跑都打印） |

## 5. 教训

1. **"测试绿"不等于"这件事被证明了"。** 判据是：把它改坏，这条测试会不会红？
   三条假的断言都不会红——它们断言的是一个恒真的东西。
2. **替身比真实快，会藏住并发缺陷。** 同步 mock 让"飞行中"这个状态根本不存在。
   要测并发性质，必须能**控制驻留点**（Event / Barrier / 显式延迟）。
3. **一个字段一个含义。** `error` 同时表示"上游报了什么"和"我们拒绝了什么"，
   必然互相覆写。拆字段比加注释有效。
4. **反直觉的数字要留在报告里。** "重试不增加单位成本"这条结论如果不写下来，
   下次讨论时一定还会有人凭直觉说"重试太贵，砍掉吧"。
