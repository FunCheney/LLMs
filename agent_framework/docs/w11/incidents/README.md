## 2. 一个必须写下来的发现：5/5 都不在四层里

W4 的 `root-cause-playbook` 是**四层决策树**（检索 / 提示词 / 工具 / 模型-可靠性），
它的第一句是"先看 `error_code`"。而这次 5 条：

| incident | 首步判据 | 结论 |
|---|---|---|
| 1 | `error_code=CONTENT_BLOCKED`，但是**我方 stage 判的**，不是上游 | 四层判据命中不了 |
| 2 | 无错误码，输出"看起来正常" | 四层判据命中不了 |
| 3 | HTTP 200 vs 401，没有 LLM 参与 | 四层判据命中不了 |
| 4 | `AUTH_INVALID`，是配置解析的结果 | 四层判据命中不了 |
| 5 | 断言/仪表，根本没有请求 | 四层判据命中不了 |

**四层归因树的前提是"系统在跑、模型在答"**，它回答"答得为什么不对"。
上线初期最常见的一类问题恰恰是"**系统没跑起来 / 跑起来了但没设防**"，
这类问题不在树里，只能靠"端到端走一遍 + 否定式断言"发现。

这不是说 playbook 没用——它在 W5–W8 把每一次质量退化都归到了具体层（检索层修法优先级
那张表就是它的产物）。结论是：**归因树要配一张"接线检查表"**，
否则所有"非模型"的故障都会被硬塞进模型层，然后去改 prompt。

## 3. 对照实验（Fork / Ablation）

两个词在这里的用法严格区分（见 `w11-tasks.md` D4 的表）：

| 实验 | 类型 | 只改了什么 | 结论 |
|---|---|---|---|
| [INC-1 §4](incident-1.md) | **Ablation** | 检测前是否先 `unwrap` | 不解封皮：拦截率仍 100%，但正常放行率 **0%**（`fake_delimiter`×6）→ 根因就是这一步 |
| [INC-5 §3](incident-5.md) | **Fork** | `max_attempts` 1 vs 3（种子固定，其余不动） | 成功率 53.0% → **87.5%**，上游调用 200 → 336，**每成功一次调用 1.89 → 1.92（几乎不变）** |

第二个结论与直觉相反，值得单独记：**重试不是"同一批成功多花两倍钱"，
而是"多花 68% 流量换来 65% 更多的成功"**，单位成本几乎持平。
容量规划看前者，策略评审看后者——混着说，讨论一定跑偏。

两条实验的断言都进了门禁：`test_ablation_still_reproduces_the_w11_incident`
（把 `unwrap` 从 `detect()` 里拿掉，红队仍 10/10，只有这条会红）。

## 4. 修复后的指标变化（诚实版）

任务书要求"修复后 history 曲线的成功率/成本有可见改善"。**这条做不到，原因是数据不存在**：

- `evals/history` 的曲线由离线 golden 集跑出来，而这 5 条里 4 条（1/2/3/4）在
  离线档根本走不到（离线不启鉴权、不跑 `deploy_check.sh`、`/v1/article` 用 mock 模型）；
- 第 5 条修的是**证据链**，它改善的是"报告是否可信"，不是成功率。

所以这里只报能报的数：

| 指标 | 修复前 | 修复后 | 来源 |
|---|---|---|---|
| `/v1/article` 首次请求 | HTTP 500 | HTTP 200 | 实跑 |
| `deploy_check.sh` | 3/5 | **5/5** | 实跑 |
| 消融 A2 正常放行率 | 0% | （修复后路径）100% | `w11_fork_ablation.py` |
| 全量门禁 | — | 1350 passed / 30 skipped | `uv run pytest` |

## 5. "最难的三个问题"（W12 面试素材候选）

1. **INC-1**：两条各自正确的防线组合起来全挂，且拦截率指标完全看不出来。
   讲的是"为什么只跑攻击样本的测试无法证伪"。
2. **INC-3**：配置项的名义 key 与实际读取的 key 是两个真相，默认值把错的那个盖住。
   讲的是"安全开关只能靠一次真实请求证明，不能靠读代码"。
3. **INC-5**：三条恒真断言 + 一个反直觉的成本结论。
   讲的是"测试绿 ≠ 这件事被证明"，以及"替身比真实快会藏住并发缺陷"。

## 6. 缺口

1. **没有外部用户反馈。** 这 5 条是自用 + 演练。真正的"用户报的 bug"要等有真实用户之后，
   而它往往长得很不一样（更偏内容质量，而不是接线）。
2. **4/5 没有 playbook 落层**，因为四层树覆盖不到"没跑起来"。补一张接线检查表是 W12 的活。
3. **修复前后没有成功率曲线**（§4 说清了原因）。要等真实流量。
