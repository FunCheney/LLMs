# 记忆与知识库的边界（W7 D4）

> 一句话：**知识库回答"我们的资料里怎么写的"，记忆回答"这个用户/这个团队
> 说过要怎么干活"**。前者是外部导入的、相对静态的、对所有人一样的事实；
> 后者是会话中产生的、随用户演化的、因人而异的偏好。
>
> Gate 7 #5 的判据文件。任何一条内容进错库，都会在两周后变成"事实被当偏好
> 忘掉"或"偏好被当事实引用"的事故。

---

## 1. 判据表（可操作，不靠感觉）

| 维度 | 知识库（`knowledge/`） | 记忆（`memory/`） |
|---|---|---|
| **谁产生** | 外部导入（PDF / 网页 / 文档同步） | 会话中产生（用户说的话） |
| **变不变** | 相对静态，版本化（`version` / `content_hash`） | 持续演化，**被顶替**（`superseded_by`） |
| **正确性来源** | 文档本身（可引用、可溯源到页/段） | 用户的说法（可溯源到会话与消息） |
| **生效范围** | 全体（受 ACL 约束） | 单个用户 / 单个团队（namespace） |
| **检索方式** | 向量 + BM25 + 精排 + ACL | 向量召回（`k≤10`）+ 活跃性过滤 |
| **注入位置** | `retrieved` 槽位（带 `[n]` 编号） | `memory` 槽位（带来源标注，无编号） |
| **失效方式** | 过期降权 / 重新索引 / 删除 | TTL 到期 / 被新值顶替 / `forget()` |
| **能不能引用** | **必须**能（回答要带 `[n]`） | **不能**当引用；它是偏好不是证据 |
| **典型内容** | 产品参数、平台规则、竞品分析、历史活动数据 | 品牌调性、禁用词、固定选题偏好、写作习惯 |
| **存储** | `rag_chunks` 表 | `agent_memories` 表（**独立表**） |
| **写入触发** | 索引流水线（`incremental.py`） | 提取器（显式记忆指令命中时） |

---

## 2. 三个判据问题（拿不准时按顺序问）

1. **"这句话是谁说的？"**
   文档里写的 → 知识库；用户说的 → 记忆。
   注意：用户**转述的文档内容**仍进知识库（来源是文档），不要因为"是用户发的"
   就写进记忆——那样它会被当偏好，过期机制也不对。

2. **"别人看到它，会不会觉得不对？"**
   会 → 知识库（事实对所有人一样）；不会 → 记忆（偏好因人而异）。

3. **"它需要被引用吗？"**
   需要 → 知识库（记忆不能当引用，见 §1 最后两行）；
   不需要、只是"让模型知道背景" → 记忆。

## 3. 五个模糊案例与裁决

| 案例 | 裁决 | 理由 |
|---|---|---|
| "我们品牌的调性是专业克制" | **记忆** | 用户会话里说的、因人而异、不需引用。虽然它"像事实"，但它是**这个团队的约定**，不是外部资料。 |
| "公司 2026 年品牌手册第 3 页写：调性专业克制" | **知识库** | 有出处、可引用、版本化。回答时要能给出"手册第 3 页"。 |
| "以后标题不要用'最'字" | **记忆** | 用户偏好 + 禁用词，写进 `forbidden_words`。它是对**生成行为**的约束。 |
| "平台规则：标题不得含绝对化用语" | **知识库** | 平台规则是外部事实，所有客户共用，要能引用出处。 |
| "上次我们讨论过露营选题" | **记忆**（`past_topics`，TTL 14 天） | 会话历史沉淀，会过时，不需要引用。若整理成了正式选题报告 → **知识库**。 |

一条实用的迁移规则：**当一条记忆开始被引用，它就该升级成知识库文档**。
"品牌调性"从记忆里被反复读出、写进对外交付物时，正确做法是把它固化成
《品牌规范 v1》进知识库，记忆里只留一句指向它的偏好。

## 4. 落到实现

### 4.1 存储隔离：表级，不是字段级

```
rag_chunks        ← 知识库（W5/W6）
agent_memories    ← 记忆（W7）
```

不塞进 `rag_chunks` 的理由：

- 检索互不污染。同一个 query 不会把记忆项混进"参考资料"列表，编号也不会
  指到记忆上；
- 结构不用模拟。记忆有 `superseded_by` / `dedupe_hash` / `confidence` 这些
  知识块没有的字段，塞进 `metadata` JSON 等于放弃约束；
- 删除语义干净。`forget()` 只影响记忆表，不会误删文档块。

### 4.2 写入路径不同

| | 知识库 | 记忆 |
|---|---|---|
| 触发 | 文档变更（手动 / 定时同步） | 显式记忆指令（"记住/以后要/不要…"） |
| 幂等键 | `content_hash` + `model_snapshot` | `dedupe_hash(key, normalize(value))` |
| 更新语义 | 同文档新版本 **替换**旧块 | 同 key 新值 **顶替**旧值（旧记录保留，`superseded_by` 指过去）|
| 拒绝策略 | 解析失败 → 整篇不入库 | `trust=external` 未确认 → 单条拒绝 |

### 4.3 读取路径不同

- 知识库：`RetrievalPipeline.run()` → 融合 → 精排 → ACL → 编号 → `retrieved` 槽位；
- 记忆：`LongTermMemory.recall(query, k)` → 活跃性/置信度过滤 → `memory` 槽位
  （不编号、不进 system）。

两条路径在 `ContextBuilder` 里汇合，各自占独立预算槽位——**互不抢预算**是
刻意的：记忆被检索挤掉，用户会感觉"它忘了我刚说的"；资料被记忆挤掉，
回答就开始编。

### 4.4 审计差异

- 知识库的答案是**可引用**的：每个事实性结论后面必须有 `[n]`，`audit_citations`
  会核对编号是否指向标注段；
- 记忆的使用是**可核对**的：`KnowledgeAnswer.memory_keys` 列出本次注入的 key，
  响应里能看出"这次到底有没有用到记忆"，不靠猜。

## 5. 两个反例（写在这里，防止下次又混）

**反例 1：把记忆当知识库**
用户说"记住：我们只做户外品类"，被当成事实写进文档库。两周后用户说
"我们拓展到家居了"，旧块还在 `rag_chunks` 里被检索命中，回答开始自相矛盾——
因为知识块没有"被顶替"语义，只有"新版本替换"语义，而它不是文档，没有版本。

**反例 2：把知识库当记忆**
平台规则"标题不得含绝对化用语"被提取成 `forbidden_words` 记忆。它现在
只对**说过这句话的那个会话**生效，而且 90 天后 TTL 到期自动消失——
所有其他用户都拿不到这条约束，回答开始违规。规则要进知识库（全体生效，
可引用），偏好才进记忆。

## 6. 与 W8/W10 的接口

- **W8（工具治理）**：工具返回的内容是 `trust=external`，既不进知识库也不进
  记忆（除非用户明确确认"记住这条"）。它的归属是 `tool_result` 槽位，用完即弃。
- **W10（权限）**：记忆的 namespace 隔离要升级成 ACL（谁能读谁的记忆）。
  本周只做到"表级隔离 + 单用户单团队"，跨租户鉴权是 W10 的事。
