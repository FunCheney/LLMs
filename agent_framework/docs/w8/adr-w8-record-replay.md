# ADR-W8-002：录制回放——离线档永不打真 API

- 状态：已采纳（W8 D2）
- 日期：2026-11-11
- 相关：`skills/replay.py`、`skills/redact.py`、`tests/test_tool_replay.py`、
  `packages/agent_framework/tests/fixtures/tools/`、ADR-010（fixture 的 `meta.synthetic`）

---

## 背景

ROADEMAP §8 把「搜索/抓取 API 不稳定且有成本」列为风险项。这不是理论风险：
外部 API 一抖动，CI 就红，而红的不是你刚改的那行代码；一有成本，跑评测的人
就会开始「少跑一点」，评测就从每天跑变成想起来才跑。

更麻烦的是**不可复现**。同一个 case，今天搜到 A 明天搜到 B，两次结果不同，
你没法判断是自己改坏了还是外部变了。

所以顺序必须是：**先录制回放，再接真 API**。反过来的话，第一周就会为了
「让 CI 绿」而去 mock，而随手 mock 出来的响应和真实结构对不上，
回放过的代码在真 API 上照样挂。

---

## 决策

### 1. 回放命中判据：`sha256(tool + canonical_args)[:16]`

```python
canonical_args = json.dumps(args, sort_keys=True, ensure_ascii=False,
                            separators=(",", ":"))
fixture_key   = sha256(f"{tool}\x00{canonical_args}")[:16]
```

三个细节各自防一种错：

| 细节 | 防的是 |
|---|---|
| `sort_keys=True` | 参数顺序不同算成两条。模型生成的 key 顺序不稳定，不排序等于每次调用都 miss |
| 把 `tool` 一起算进哈希 | 不同工具收到同样参数是常态（`{"url": ...}`）。只用参数哈希会让它们撞到同一个文件，然后回放出**错误的结果**——这类错误不报错，只让答案悄悄变错 |
| `ensure_ascii=False` | `\u4e2d\u6587` 在 diff 里没法 review。夹具是给人看的资产 |

### 2. `record=False` 未命中必须**明确报错**

抛 `ReplayMissError`，**绝不联网**。

「偷偷联网」是最坏的一种设计：CI 偶发绿、指标偶发飘、排查时无论如何复现不出来。
它还有一个隐蔽的变体——「未命中时用一个空结果兜底」，看起来不联网，
实际让评测在缺数据时判成通过。两者都会把「缺夹具」伪装成「跑通了」。

报错消息里带 `tool` 与规范化后的 `args`，让人能直接去补夹具。

### 3. 落盘前脱敏

`redact.sanitize` 在写文件**之前**跑。规则与 W1 Day5 同一套：

| 类型 | 处理 |
|---|---|
| 键名命中（`api_key` / `token` / `authorization` / `secret`…） | 值换 `***`，**不 pop 键** |
| 值形态命中（`sk-…` / `ghp_…` / `Bearer …`） | 保留前缀与尾 4 位 |
| URL 里的 query 参数 | 敏感键打码，路径保留 |

为什么键名命中时**不 pop**：打过码的键被删掉，夹具里看起来就像「服务器本来
没返回这个字段」。下次 review 时没人知道这里曾经有密钥，也就没人会去检查
打码逻辑对不对。

为什么不用「全文扫描 + 替换」兜底：会把正文里正常出现的词也打掉，
造出一批「看起来像密钥」的假阳性，然后大家开始忽略打码结果。

### 4. 回放标记与成本必须回流

`_meta.replayed = true`，且 `cost = 0`，但**报告里要分开统计**。

放在 `_meta` 而不是顶层：`_meta` 是 MCP 协议预留位，顶层多一个 `replayed`
字段会被严格的 server 拒绝（`additionalProperties: false`）。这是协议约束，
不是风格选择。

为什么成本必须分开：W11 要做成本看板。回放成本记 0 但不标记，
看板上的「本周工具成本」会显示 0，而真实调用可能正在烧钱——
**看板失真的方式不是数字错，是数字对得让人放心**。

### 5. 超大响应不录、不报错

`MAX_FIXTURE_CHARS = 200_000`。超限时不落盘（避免仓库里塞进几个 MB 的 HTML），
但也不抛错——录制一次抓取就失败会让整条录制链断掉。
代价是这条 case 将来在离线档会 miss，所以超限时会记一条 warning。

### 6. fixture 带 `meta.synthetic`

沿用 ADR-010：手写的桩数据与真录制的数据必须可区分。
否则「这个 case 一直通过」可能只是因为你自己的桩编得太好。

## 后果

### 好的

- 断网跑自检 23/23（`evals/scripts/tool_boundary_check.py`，默认档 `replayed=True cost=0.0`）。
- 删掉一条夹具 → 明确 `ReplayMissError`，不联网（反向验证也有用例）。
- 录一条含 `sk-live-…` 的响应 → 落盘文件里是 `sk-l***…abcd`。

### 代价

- 夹具是**要维护的资产**。server 改了返回结构，夹具不会自动跟着变——
  这是想要的：它逼你在改契约时同步更新夹具，而不是让 CI 悄悄继续跑旧结构。
- 回放过的路径不等于真 API 上也对。所以每条真 API 路径仍要有一个
  `-m live` 的用例（默认跳过），录制档不能替代它。

### 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 未命中时联网兜底 | CI 偶发绿、指标偶发飘、排查不可复现 |
| 未命中时回空结果 | 把「缺夹具」伪装成「跑通了」，比联网更隐蔽 |
| 只用参数哈希做键 | 不同工具同参数会撞，回放出错误结果且不报错 |
| 回放成本照抄真实成本 | W11 成本看板失真 |
| 把 `replayed` 放响应顶层 | 严格 server 会拒（`additionalProperties: false`） |
| 脱敏时才 pop 敏感键 | 夹具看起来像「本来没这个字段」，打码逻辑失去 review 入口 |
