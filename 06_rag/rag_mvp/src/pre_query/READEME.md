## 查询前处理
在 RAG 系统中，查询前处理（Query Preprocessing） 是指用户提出问题之后、正式进入检索之前，对原始 Query 进行分析、改写、补充或转换，使它更容易检索到正确的知识。

查询前处理主要完成如下的功能：
1. 查询校验规范化
   检查输入是否为空、是否超长、清理多余空格、统一全角半角符号，规范化常见格式。
2. 查询意图识别
   判断用户是要查定义、查配置、定位错误、比较概念，还是询问文档中不存在的内容，从而选择合适的检索策略。
3. 查询改写
   修正表达不清、口语化、缩写不统一等问题，在不改变用户原意的前提下，让查询更适合检索。
4. 上下文补全
   将依赖历史对话的指代、简称或省略表达补全为独立问题。
5. 查询扩展与多查询生成
   为原始查询生成同义表达、相关术语或多个检索视角，再合并结果，提高召回率。
6. 查询分解
   将包含多个子问题或推理步骤的问题拆分，分别检索，再汇总结果。
7. 检索策略路由
   根据查询类型决定使用 Dense、BM25、Hybrid，是否需要元数据过滤，以及是否需要多查询检索。
8. 元数据提取
   从问题中识别章节、产品版本、文档类型、时间范围等过滤条件，并传递给检索层。

## 如何证明查询前处理有效
查询改写不一定会提升检索效果。错误的改写可能丢失错误码、产品名、版本号等关键字，反而导致召回率下降。

经有 Smoke Retrieval 和 Golden Dataset 的基础，可以复用同一套测试集，设计三个实验：

1. 实验 A：Baseline
   原始 Query → Hybrid Search → RRF
   记录 Hit@5、Recall@5、平均检索延迟。
   
2. 实验 B：Normalization
   规范化后的 Query → Hybrid Search → RRF
   检查格式清理是否影响精确名称、错误码等查询。

3. 实验 C：Rewrite
   改写后的 Query → Hybrid Search → RRF
   比较检索指标，同时检查关键实体是否被保留。

比较时需要固定语料、索引、Top-K 和评估集。对于多查询检索，还应统计合并后的结果，并将额外延迟和调用成本纳入评估。
